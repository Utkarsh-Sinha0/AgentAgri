### D0 — Demo session bridge (security contract)

- `POST /api/auth/demo-session?role={farmer|extension_worker}&identity={seeded_id}` requires `X-Bot-Demo-Secret` header (constant-time compare, min 32 chars).
- Identity must be in `settings.demo_allowed_farmers` (default `["farmer_demo_munger_001"]`) or `settings.demo_allowed_workers` (default `["worker_demo_extension_001"]`).
- Per-IP rate limit: 6 mints/min (in-memory Phase 0a; Redis Phase 3).
- Returns HMAC-SHA256 signed bridge token `{aud:"agri-pwa", sub, role, exp:now+5min, jti, single_use:true, kid}` plus `Set-Cookie: __Host-agri_session=...; HttpOnly; Secure; SameSite=Strict; Path=/`.
- Bridge token is single-use; `jti` recorded in dedup store.

**HMAC key rotation**: two-key system `bot_demo_secret_current` + `bot_demo_secret_previous`. Token carries `kid`; verifier picks key by `kid`. Rotation = env swap; already-issued 5-min tokens remain valid until natural expiry. No forced invalidation needed.

**JTI cleanup**: Phase 0a uses `OrderedDict[jti, exp_ts]` capped at 10k entries with LRU eviction + 60s sweep removing expired entries. Restart drops the map (acceptable: ≤5-min replay window). Phase 1 migrates to `used_jti(jti UUID PK, exp_ts, created_at)` table with nightly cleanup.

**Demo secret lifecycle**: generated by `scripts/gen_secrets.py` (`secrets.token_urlsafe(32)`). Stored in container env; API and Telegram bot read same source. Rotation via env update + redeploy; overlap covered by `_previous` slot. Documented in `docs/operations/demo-deployment.md`.

**Environment policy**: `app_env` enum: `development | test | demo | production`. C6 validator in production: all demo settings must be empty/False. In `demo`: `bot_demo_secret_current` must be ≥32 chars.

### Authorization rules
- `authorize_farmer(session, path_farmer_id)`: True iff `session.farmer_id == path_farmer_id` AND `session.revoked_at IS NULL` AND `session.expires_at > now()`. Hypothesis property test.
- `authorize_worker_for_cluster(worker, cluster)`: `worker.district == cluster.district` AND (`worker.tehsil IS NULL OR worker.tehsil == cluster.tehsil`) AND (`worker.assigned_villages == [] OR cluster.village IN worker.assigned_villages`). 8-row truth-table test.

### Cookie + session semantics
- `__Host-` prefix forces Secure + Path=/ + no Domain. CSRF double-submit via `X-Csrf-Token` header + `agri_csrf` companion cookie (non-HttpOnly).
- Session rotation on privilege change: single-tx `UPDATE revoked_at=now() WHERE id=:old` then `INSERT` new row; new `Set-Cookie` overwrites prior; CSRF token also rotated.
- Concurrent sessions allowed (`(farmer_id, source)` not unique); revocation per-row.
- Cleanup job (Phase 3): delete rows where `expires_at < now() - 7 days`.

### CSRF bootstrap for Telegram deep-link
1. Bot URL: `https://demo.../?bridge_token=<signed>`.
2. PWA `POST /api/auth/exchange { bridge_token }` (idempotent on jti).
3. Server validates HMAC + exp + jti unused; INSERTs session row; sets `__Host-agri_session` (HttpOnly) and `agri_csrf` (non-HttpOnly); returns `{csrf, farmer}` JSON.
4. PWA stores CSRF in module state, re-reads from `agri_csrf` cookie on each page load.
5. Subsequent non-GET include `X-Csrf-Token`; server checks header == cookie.

### Dev backdoor (C3)
`X-Agrimesh-Dev-Farmer` accepted iff: `settings.enable_dev_farmer_header == True` AND `app_env in {development, test}` AND request from loopback. Default False everywhere. C6 refuses in demo + production.
